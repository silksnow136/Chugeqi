# 需求分析（楚歌起 Chugeqi）

> 本文是项目的前置需求文档，回答「要做什么」。文中用 ✅（已实现）/ 🔶（部分实现）/ ⬜（未实现）标注当前落地情况，便于与代码现状对照。

---

## 1. 引言

### 1.1 编写目的

明确「楚歌起」的功能范围、玩法规则、数据需求与质量要求，作为软件设计与编码实现的依据，并作为验收对照。

### 1.2 项目范围

- **做**：Windows 控制台回合制战斗 RPG 原型，含角色、技能、物品、战斗、存档、数据配置化加载；剧情框架（四幕）预留。
- **不做**：图形界面、网络/多人、音效、自动测试框架（原型阶段）。

### 1.3 术语

| 术语 | 含义 |
|------|------|
| 四维属性 | 力量（物理输出）、魔力、耐力（防御）、敏捷（命中/逃跑） |
| HP / SP | 生命值 / 技力值（施放技能消耗） |
| 模板 | JSON 中定义的角色/技能/物品初始定义，只读 |
| 存档 | SQLite 数据库 `save.db` 中玩家的运行时状态 |
| 幕 | 剧情章节，全篇四幕（垓下 → 淮河 → 东城 → 乌江） |

## 2. 项目概述

### 2.1 背景与定位

取材项羽人生终章「垓下之围 → 乌江自刎」，四幕推进：

| 幕 | 地点 | 情节 |
|----|------|------|
| 第一幕：四面楚歌 | 垓下 | 被围、楚歌四起、霸王悲歌 |
| 第二幕：突围南逃 | 垓下 → 阴陵 → 淮河 | 八百骑突围渡淮，左右支线（右遇王翦、左陷沼泽） |
| 第三幕：东城快战 | 东城 | 二十八骑斩将刈旗，连斩小将秦时月 |
| 第四幕：乌江自刎 | 乌江 | 虞姬自刎，冲阵连斩，霸王落幕 |

### 2.2 目标用户与操作方式

- 单机、单人；键盘数字键 + 方向选择的纯文字交互（原 MUD 血统）。
- 玩家循环：**开始游戏（建档/读档）→ 探索（查看/拾取/对话）→ 触发战斗 → 结算存档 → 推进剧情**。

### 2.3 主要人物设定（数值来自背景设定）

| 人物 | 力量 | 敏捷 | 防御 | 最大生命 | 备注 |
|------|------|------|------|----------|------|
| 项羽 | 90 | 70 | 80 | 150 | 装备霸王枪、乌骓马 |
| 虞姬 | 40 | 80 | 60 | 110 | 同伴 |
| 王翦 | 80 | 60 | 60 | 130 | 第二幕敌方，装备披云枪、逐月马 |
| 秦时月 | 60 | 40 | 60 | 110 | 第三幕敌方小将，装备长虹枪、步云马 |

> 原型阶段先以通用测试模板（player/伙伴/测试敌人）验证系统，剧情数值接入为后续工作。

## 5. 非功能需求

| 编号 | 类别 | 需求 | 状态 |
|------|------|------|------|
| NFR-01 | 可移植性 | 平台差异（清屏/按键/编码）集中在单一抽象层，业务代码不直接依赖平台 API | ✅ |
| NFR-02 | 本地化 | 控制台中文 UTF-8 正常显示（Windows 下设置代码页） | ✅ |
| NFR-03 | 性能 | 原型无实时性要求；数据量小，加载 < 1s | ✅ |
| NFR-04 | 内存安全 | 资源所有权明确，不手动 new/delete 裸管理；程序退出无泄漏 | ✅ |
| NFR-05 | 可维护性 | 模块单一职责；头文件接口与实现分离；避免循环包含（前向声明） | ✅ |
| NFR-06 | 数据健壮性 | 文件缺失/JSON 语法错误时报错退出并给出原因，不静默出错数据 | ✅ |
| NFR-07 | 可扩展性 | 新增技能/角色/战斗仅需增改 JSON；新增技能类型仅需新增派生类 + 分派分支 | ✅ |

## 6. 数据需求（分层）

| 分层 | 内容 | 存储 | 生命周期 |
|------|------|------|----------|
| 静态模板 | 技能池、物品池、敌人模板、战斗配置 | JSON（`data/`） | 启动载入一次，只读，长期持有 |
| 运行时持久状态 | 队伍 HP/SP/等级/经验、技能、背包 | SQLite（`save.db`） | 跨运行会话 |
| 战斗临时数据 | 战斗者实例、战斗日志 | 内存 | 一场战斗结束即释放 |

---

## 7. 约束与假设

- 运行平台优先 Windows（conio/UTF-8），其他平台降级可用。
- SQLite 以官方合并源码直接编入工程，不依赖外部安装。
- 原型阶段数值平衡不重要，重在机制正确与数据可配置。
- 假设用户通过键盘数字键完成所有交互。

---

## 8. 验收标准

1. `cmake` 配置 + 编译零错误，产物可运行。
2. 首次运行自动建档；可完成一场完整战斗（攻击/技能/逃跑/胜利结算）。
3. 战后重开程序，等级/经验/HP/SP 保留；选重置后回到初始模板。
4. 修改 `data/` 下 JSON（如调属性、加技能）重启后生效。
5. 数据文件缺失或 JSON 损坏时，程序报明确错误并退出，不崩溃悬挂。
