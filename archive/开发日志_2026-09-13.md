# 开发日志

本文记录「楚歌起 (Chugeqi)」的开发进度与现状，面向项目成员。

> 旧版开发日志已归档至 `archive/开发日志_旧版.md`。

---

## 1. 项目概述

「楚歌起」是以楚汉相争、项羽垓下之围至乌江自刎为背景的控制台回合制 RPG，由两个项目合并而成：

- **Chugeqi**：战斗内核（回合制战斗、角色/技能/物品、SQLite 存档、JSON 数据加载）。
- **TheFalloftheOverlord**：剧情外壳（四幕剧情、场景、对话、地图、逐字打印）。

技术栈：C++17 + CMake + 自研 JSON 解析器 + SQLite（官方合并源码）。

核心设计思想是「数据分层」：

| 分层 | 内容 | 存储方式 |
|------|------|----------|
| 静态模板 | 技能池、物品池、装备池、剧情文本、对话文本、敌人模板 | JSON 文件，启动时载入一次 |
| 运行时持久状态 | 队伍 HP/SP、等级/经验、技能/道具、装备 | SQLite（`save.db`） |
| 临时数据 | 一场战斗的战斗者、场景状态 | 内存，随流程释放 |

## 2. 开发进度

### 2.1 战斗原型（Chugeqi 早期）

- 回合制战斗：玩家 + 同伴手动操作，普攻 / 伤害技能 / 治疗技能 / 逃跑。
- 命中与伤害计算：基于敏捷的命中率、`力量 × 威力 − 防御` 的伤害公式。
- 角色成长、技能/物品类层次、自研 JSON 解析器、SQLite 三表存档。
- 平台抽象层 `console`（清屏 / 按键 / 编码）。

### 2.2 状态效果大修

- 实现灼烧 / 迟缓 / 眩晕 / 充能四种状态效果。
- 结算统一到战斗主循环每轮开始（灼烧扣血、迟缓提示）与轮末（持续回合递减）。
- 属性修正（迟缓降敏捷、充能提属性）集中在 `Combatant::getEffectiveStat`。
- 保留并完善敌人 AI（回击、技能选择、集火残血）与我方 AI 托管。

### 2.3 TheFalloftheOverlord 移植

- 全源码 GBK → UTF-8，移除 `windows.h` / `conio.h` 依赖，接入 `console` 平台抽象。
- 构建由 `.sln` / `.vcxproj` 改为 CMake。
- 剧情文本抽离为 `data/story.json`，由 `loadStory` 解析（旁白/对话/分支结构）。

### 2.4 合并两个仓库

- 用 `git merge --allow-unrelated-histories` 把 TheFalloftheOverlord 合并进 Chugeqi，保留两个仓库的完整提交历史。
- 统一 console 层、去重 `json.h`、合并 CMakeLists、以 `main.cpp`（剧情）为主入口。

### 2.5 目录重构 + 统一数据加载

- 源码按职责拆为 `src/core/`（平台抽象 + 数据加载）、`src/combat/`（战斗）、`src/story/`（剧情）。
- 剧情数据结构（`StoryLine`/`Scene`/`StoryData`）与 `loadStory` 并入 `DataLoader`，实现战斗与剧情的统一加载入口。
- CMake 拆出两个目标：`Chugeqi`（主游戏）与 `combatTest`（战斗测试）。

### 2.6 装备系统

- `item.h` 新增 `Equipment`（`EquipmentSlot`：Armor/Weapon/Shoes/Accessory）与 `bonus[4]` 属性加成。
- `Combatant` 新增四槽位管理：`equipItem` / `unequipItem` / `getEquippedItemId`，属性加成叠加进 `getEffectiveStat`。
- `DataLoader::loadItems` 支持解析装备（`type=equipment` + `slot` + `bonus`）、消耗品、材料，并按 `category` 分类。
- `data/item.json` 扩展至 18 件物品（消耗品 / 6 件装备 / 材料）。

### 2.7 药店系统

- `PharManager` 实现：`showShop`（列出药水）、`buyItem`（金币购买）、`useItem`（回 HP/SP）、`showMedicineBag`。
- `Game` 持有 `gold` 与 `ItemPool`，`SceneManager` 在 PHARMACY 状态下按需创建 `PharManager`。

### 2.8 对话系统 JSON 化

- `TalkManager::loadDialogue` 按 `scene_id`/`branch_id`/`character_id` 从 `data/talk.json` 读取并逐句播放。
- 第二幕对话按 `branches` 区分（分支 A 王翦/汉军、分支 B 副将）。
- `talk.json` 扩充至 737 行，各幕角色对话已填充。

### 2.9 网格地图系统（MapGrid）

- `MapGrid`：二维网格，每格固定 4 列宽（含中文宽度计算与补齐）；WASD 移动、边界/碰撞检测。
- `TileType`：EMPTY/WALL/PLAYER/FRIEND/ENEMY/PHARMACY/FORGE/DOOR/ITEM。
- 交互：友方→对话、敌方→战斗、药店→购买、铁匠铺→锻造、物品→拾取（消失）、门→通行。
- 建造方法：`buildRoom`（房间+门）/`buildFence`（栅栏）/`buildCheval`（拒马）/`buildWater`（水域）。
- 渲染防闪烁：首屏 `clearScreen`，后续 `moveCursor` 覆盖 + `clearToEnd` 清残留，`setCursorVisible` 隐藏光标。
- 四张拟物场景地图：`gaiXiaMap`（37×27 垓下营地）、`huaiRiverMap`（37×27 淮河突围）、`dongchengMap`（27×27 东城快战）、`wujiangMap`（27×27 乌江自刎）。
- 背包界面 `showBackpack`：显示装备/药水/材料分组，`equip+编号`/`unequip+编号`/`use+编号`。

### 2.10 平台层扩展 + Linux 兼容

- `console` 从 8 函数扩展到 11 函数：新增 `moveCursor` / `setCursorVisible` / `clearToEnd`。
- Linux 分支：ANSI 清屏、方向键转义序列解析（`KEY_UP/DOWN/LEFT/RIGHT`）。
- 添加 `.gitattributes` 统一 LF 换行符。

## 3. 当前功能现状

### 3.1 剧情系统（`src/story`）

- 四幕剧情（垓下/阴陵/东城/乌江），从 `data/story.json` 加载。
- `SceneManager` 场景状态机：`ORIGIN_SCENE` / `TALK` / `PHARMACY` / `FORGE`。
- `printWords` 逐字打印（含 UTF-8 中文按 3 字节切分）、`nextLine` 自动/手动切换（ESC）、按 q 加速。
- 第二幕分支（田父指路 A/B）由 `StoryChoice`/`StoryOption` 表达，`playChoice` 处理选择。
- `TalkManager` 从 `talk.json` 加载各角色对话并播放。

### 3.2 战斗系统（`src/combat`）

- 回合流程：玩家 → 同伴 → 敌方，循环至一方全灭或逃跑。
- 普通攻击、伤害/治疗/充能技能、逃跑。
- 敌人 AI：回击，约 60% 概率施放技能、集火残血；我方支持 AI 托管（ESC 退出）。
- 状态效果：灼烧（回合开始扣血）、迟缓（敏捷 ×3/5）、眩晕（跳过行动）、充能（属性 ×倍率）。
- 装备：四槽位属性加成；经验与升级、SQLite 存档。

### 3.3 物品 / 装备（`src/combat`）

- `Item` 基类 → `Consumable`（回 HP/SP、临时属性加成）、`Equipment`（四槽位属性加成）。
- `ItemPool` 由 `DataLoader` 持有，按 `id` 索引。
- 背包：`showBackpack`（`MapGrid.cpp` 内）支持装配/卸下/使用。

### 3.4 平台抽象（`src/core`）

- `console`：`init` / `clearScreen` / `readKey` / `pause` / `pauseEsc` / `setColor` / `sleep` / `kbhit` / `moveCursor` / `setCursorVisible` / `clearToEnd`。
- `json.h`：轻量递归下降 JSON 解析器（只读）。
- `dataLoader`：统一加载技能、物品/装备、角色、战斗配置、剧情。

## 6. 测试方法

### 6.1 构建

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build
```

编译无报错即通过基础构建测试。共 7 个目标：`Chugeqi`、`combatTest`、`mapTest`、`gaiXiaMap`、`huaiRiverMap`、`dongchengMap`、`wujiangMap`。

### 6.2 剧情测试（`Chugeqi`）

1. 启动后输入 `1` 开始游戏，观察四幕剧情逐字播放。
2. 输入 `auto` / `manual` 切换自动/手动播放；播放中按 ESC 切换，按 q 加速。
3. 输入 `map` 查看世界地图；`south`/`north` 推进/回退剧情；`start` 回主界面。
4. 第二幕田父指路处，输入 `A`/`B` 验证两条分支（王翦/沼泽）剧情不同。
5. 进入场景后输入 `1` 对话、`2` 药店、`3` 锻造（锻造仍为占位）。

### 6.3 战斗测试（`combatTest`）

1. 普通攻击、技能（火球/治疗/聚力）、逃跑。
2. 状态效果：火球附加灼烧（回合开始扣血）、聚力进入充能（属性提升）、观察状态栏显示。
3. 敌人 AI：敌方会回击；按菜单开启我方 AI 托管，ESC 退出。
4. 存档：战斗结束后写回 `save.db`，再次运行验证等级保留；选 `Y` 重置。

### 6.4 地图测试（`mapTest`）

1. WASD 控制项羽移动；边界墙壁不可穿越。
2. 碰到友方单位触发对话；碰到敌方单位触发**真实战斗**（接 `CombatSystem` + 存档读写）。
3. 碰到药店 / 铁匠铺触发对应交互（测试里为占位文本）。
4. ESC 退出。

### 6.5 地图展示（`gaiXiaMap` 等四个）

1. WASD 移动、B 打开背包（装配/卸下/使用）。
2. 拾取物品（ITEM 格）验证入包与消失。
3. 带任意参数运行只渲染一次即退出。

### 6.6 修改 JSON 数据测试

- 改 `data/story.json` 的文本/颜色/分支，重跑 `Chugeqi` 验证剧情变化。
- 改 `data/skill.json` 或 `data/player.json` 的数值，重跑 `combatTest` 验证战斗数值变化。
- 改 `data/item.json` 装备 `bonus` 或药水 `healHP`，重跑 `gaiXiaMap` 开背包验证。

> JSON 语法错误会触发解析器异常，可借此验证错误处理。
