## 1. 设计目标与原则

| 原则 | 落地方式 |
|------|----------|
| 数据驱动 | 技能/角色/战斗配置全部外置 JSON，程序只是"解释器" |
| 数据分层 | 静态模板(JSON) / 持久状态(SQLite) / 战斗临时(内存) 三层隔离 |
| 所有权明确 | 拥有用 `unique_ptr`，借用用裸指针，禁止双向拥有 |
| 平台隔离 | 控制台差异收敛到 `console` 一个模块 |
| 为扩展预留 | 状态效果、AI、道具、剧情均先定数据结构与接口占位 |

## 2. 总体架构

```
┌────────────────────────────────────────────────────┐
│              应用层 combatTestMain.cpp              │
│        流程编排：载入→读档→战斗→存档→重置询问        │
├─────────────────────────┬──────────────────────────┤
│      战斗系统            │      探索/剧情（预留）    │
│     CombatSystem         │   地图/对话/任务/背包UI   │
├─────────────────────────┴──────────────────────────┤
│  领域对象层（无 IO，纯数据+规则）                    │
│  Character/Civil/Combatant  SkillBase 及三派生      │
│  Item/Consumable/Equipment   StatusEffect          │
├──────────────┬─────────────────┬───────────────────┤
│ DataLoader   │ SaveManager     │ console / BattleLog│
│ (JSON→对象)  │ (SQLite↔对象)   │ (平台抽象/显示)    │
└──────────────┴─────────────────┴───────────────────┘
      │                │
   data/*.json      save.db
```

依赖方向自上而下单向；`character.h` 与 `skill.h` 互相需要时用前向声明断开循环包含。

## 3. 模块职责

| 模块 | 职责 | 不负责 |
|------|------|--------|
| `combatTestMain` | 组装各模块、执行"载入→战斗→存档"主流程 | 任何规则计算 |
| `combatSystem` | 回合流程、菜单交互、行动执行、命中/伤害计算、战斗界面 | 持有对象生命周期 |
| `character` | 角色数据与自身规则（受伤/治疗/状态增删/升级/背包增减/拾取查看） | 主动发起战斗 |
| `skill` | 技能数据与单技能数值计算（`calculateDamage`） | 执行目标选择与结算 |
| `item` | 物品数据定义 | 使用效果结算（在战斗/探索层） |
| `dataLoader` | JSON → 领域对象；静态模板唯一创建入口 | 运行时写回 |
| `saveManager` | 队伍状态 ↔ SQLite 三表 | 创建领域对象之外的逻辑 |
| `battleLog` | 滚动日志的存储与格式化 | 直接打印（由调用方输出） |
| `console` | 清屏/按键/编码/暂停的平台封装 | 任何游戏逻辑 |
| `json.h` | 只读 JSON 解析（递归下降） | 写出 JSON |

## 4. 类设计

### 4.1 类层次

```
Character {name}
├── Civil {role, dialogue[]}                 # 剧情 NPC
└── Combatant {id, hp, sp, level, exp,
               baseStats[4], equipmentBonus[4],
               statusFlags, activeStatusEffects[],
               skills[], inventory{itemId→count}}

SkillBase {name, description, cost, scope}
├── DamageSkill   {power, statusEffect, hitRate}
├── HealSkill     {healAmount}
└── ChargingSkill {multiplier, targetStat, duration}   # 执行预留

Item {id, name, description, price}
├── Consumable {healHP, healSP, statBonus, statIndex, duration}
└── Equipment  {slot: Armor|Weapon|Shoes|Accessory, statBonus[4]}
```

### 4.2 Combatant 关键方法

| 方法 | 说明 |
|------|------|
| `getEffectiveStat(i)` | `baseStats[i] + equipmentBonus[i]`，唯一对外属性出口 |
| `takeDamage / heal / restoreSP` | HP 下限 0；heal 暂不设上限 |
| `addStatusEffect / updateStatusEffects / clearStatusEffect` | 同类型刷新时长；每回合末递减并移除到期；变更后重算位标志 |
| `addItem / consumeItem / hasItem / getItemCount` | 背包上限 99；耗尽即删除键 |
| `addExp / levelUp` | 曲线 `10×level²`；升级全属性+1、HP=100+10L、SP=50+5L、上限 99 级 |
| `pickUp / showStats / showInventory` | 探索态交互（拾取反馈、查看属性/背包） |

### 4.3 所有权设计（核心约定）

```
拥有（unique_ptr）                    借用（裸指针）
─────────────────                    ─────────────
GameData::skillPool    ───被引用───→  Combatant::skills
Battle::enemies        ───被引用───→  CombatSystem::enemies
main 的 party          ───被引用───→  CombatSystem::player/companions
```

- `SkillPool = unordered_map<string, unique_ptr<SkillBase>>`：技能对象的唯一拥有者，长期存活。
- `CombatSystem` 析构不释放任何参战对象（由调用方的 `unique_ptr` 管）。
- 存档写回需要 id：`saveParty` 用 `findSkillId` 把技能指针**反查**回 skill_id。

## 5. 关键机制设计

### 5.1 战斗回合流程

```
startBattle:
  while 未结束:
    玩家存活 → manualTurn(player, 4项菜单)      # 攻击/技能/道具/逃跑
    敌人全灭 → 胜利跳出
    for 同伴: manualTurn(companion, 2项菜单)    # 攻击/技能（手动操控）
    敌人全灭 → 胜利跳出
    for 敌人: processEnemyTurn()                # 预留：AI 未实现，暂空转
  胜利 → 经验结算（Σ 敌等级×10，全队）
  输出结果与最终界面
```

- `manualTurn` 内：行动前刷新界面 → 读菜单键（0/ESC 可返回上级）→ 执行 → 再刷新 → 暂停。
- 单体技能/普攻手动选目标（仅一个候选时跳过选择）；全体技能自动选中全部存活者，治疗全体=全队、攻击全体=全部敌人。

### 5.2 数值公式

| 项目 | 公式 | 备注 |
|------|------|------|
| 命中率 | `base × atkAgi/(atkAgi+defAgi) + 0.05` | 夹在 `[0.10, 0.99]`；普攻 base=0.95，技能 base 来自配置（默认 0.95） |
| 伤害 | `力量 × 威力 − 耐力` | 下限 0；普攻威力 10，技能威力来自配置 |
| 逃跑 | `roll(100) < selfAgi×100/(selfAgi+Σ敌Agi)` | `disable_run` 时直接失败提示 |
| 升级经验 | `10 × 等级²` | 跨级经验循环结算 |
| 胜利经验 | `Σ(敌人等级 × 10)` | 全队共享同一数值 |

### 5.3 状态效果：位标志 + 实例列表

```cpp
enum class StatusEffect : uint16_t { None=0, Burn=1<<0, Slow=1<<1, Stun=1<<2, Charge=1<<3 };

struct StatusEffectInstance { type; duration; targetStatIndex; multiplier; };
```

- `statusFlags`：所有活跃状态按位或，O(1) 判断"是否处于某状态"。
- `activeStatusEffects`：保存每条状态的剩余回合与数值（充能的目标属性/倍率）。
- 两级结构兼顾"快速判断"与"携带数据"，由 `recalcStatusFlags()` 保持一致。
- **结算入口已预留**：`applyBurnDamage / applySlowEffect / checkStun / applyStatusEffects`（现为空实现）。

### 5.4 技能执行：dynamic_cast 分派

技能对象只带数据，执行逻辑集中在 `performSkill` 内按实际类型分派：

```cpp
if (auto* d = dynamic_cast<DamageSkill*>(skill)) { ... }      // 命中→伤害
else if (auto* h = dynamic_cast<HealSkill*>(skill)) { ... }   // 恢复
else { /* ChargingSkill：预留 */ }
```

理由：技能数量少、类型稳定，集中分派便于在结算处统一插入"附带状态""充能"等横切逻辑；避免在十几处写虚函数回调。

### 5.5 随机数

`std::mt19937`（`random_device` 播种）+ `uniform_int_distribution`，封装为 `roll(upper)` 返回 `[0, upper)`，全系统唯一随机入口，便于将来替换/回放测试。

### 5.6 平台抽象 `console`

| 接口 | Windows 实现 | 其他平台 |
|------|--------------|----------|
| `init()` | `SetConsoleOutputCP/CP_UTF8` | 空 |
| `clearScreen()` | `system("cls")` | `system("clear")` |
| `readKey()` | `_getch()`（无回显） | `getchar()` |
| `pause()` | `_getch()` | `getchar()` |

### 5.7 战斗日志

`std::deque<string>`，上限 7 条：`add` 超限弹头；`render()` 恒定输出 7 行（不足补空行，整体居中「(暂无)」），供界面固定区域渲染。

## 6. 数据设计

### 6.1 JSON 模板规范

**skill.json**（键 = 技能 id）

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| type | string | 否(默认 damage) | damage / heal / charge |
| name / description | string | name 必填 | |
| cost | int | 否(0) | SP 消耗 |
| scope | string | 否(single) | single / all |
| power | int | damage 必填 | 威力 |
| statusEffect | string | 否(none) | burn / slow / stun / charge |
| hitRate | float | 否(0.95) | 基础命中率 |
| healAmount | int | heal 必填 | 治疗量 |
| multiplier / targetStat / duration | float/int | charge 用 | 倍率 / -1全属性或0~3 / 回合数 |

**角色模板**（player/companion/enemy 通用）

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | string | 我方必填 | 存档主键；敌人可省 |
| name / level / hp / sp | - | hp/sp 必填 | level 默认 1 |
| exp | int | 否(0) | |
| baseStats | int[4] | 否(0,0,0,0) | 力/魔/耐/敏 |
| skills | string[] | 否 | 技能 id 列表（在 skillPool 中解析） |
| inventory | object | 否 | itemId → 数量 |

**battle_*.json**（战斗配置）

| 字段 | 说明 |
|------|------|
| player_ref / companions_ref(或 companion_ref) / enemies_ref | 引用同目录角色模板文件（相对路径） |
| first_side | player / enemy（预留） |
| disable_run / disable_items | true 时禁止逃跑 / 禁止道具 |

### 6.2 SQLite 表结构（save.db）

```sql
CREATE TABLE IF NOT EXISTS characters (
  id TEXT PRIMARY KEY, name TEXT NOT NULL, level INTEGER NOT NULL,
  hp INTEGER NOT NULL, sp INTEGER NOT NULL, exp INTEGER NOT NULL,
  str INTEGER NOT NULL, mag INTEGER NOT NULL,
  endur INTEGER NOT NULL, agi INTEGER NOT NULL);

CREATE TABLE IF NOT EXISTS learned_skills (
  character_id TEXT NOT NULL, slot INTEGER NOT NULL, skill_id TEXT NOT NULL,
  PRIMARY KEY(character_id, slot));

CREATE TABLE IF NOT EXISTS inventory (
  character_id TEXT NOT NULL, item_id TEXT NOT NULL, count INTEGER NOT NULL,
  PRIMARY KEY(character_id, item_id));
```

- 一对多关系（技能/物品）拆表规范化，`character_id` 外键关联。
- 写入流程：预编译占位符语句 → 绑定参数 → step → finalize，统一封装于 `runStatement`；存档清空/写回使用事务保证原子性。

### 6.3 id ↔ 指针双向映射

- 读档：`loadParty` 读出 skill_id，在 `skillPool` 中**正查**得到指针注入角色。
- 存档：`saveParty` 遍历 `skillPool`，把技能指针**反查**（`findSkillId`）为 id 入库。
- 该约定要求：运行期间不得向 `skillPool` 外部来源注入无名技能。

## 8. 错误处理设计

- **启动期失败即退出**：文件打不开、JSON 语法错误、SQLite 建表失败 → 抛 `std::runtime_error`（含原因），`main` 捕获后输出 `错误: ...` 并返回 1。
- **运行期可恢复**：SP 不足、取消选择（0/ESC）、非法菜单键 → 提示后回到原菜单，不中断战斗。
- 数值下限保护：HP ≥ 0、伤害 ≥ 0、属性索引越界返回 0。

## 9. 构建与部署设计

- CMake ≥ 3.15，C++17；MSVC 下追加 `/utf-8`（源码中文）与 `/W0`（屏蔽第三方告警）。
- SQLite 以 `third_party/sqlite/sqlite3.c` 直接编入，头文件目录 `target_include_directories` 注入。
- `POST_BUILD` 把 `data/` 整目录复制到 exe 同级 → **保证相对路径 `data/` 在运行目录可见**；`save.db` 亦生成于运行目录。

## 11. 设计决策记录（Why）

| 决策 | 理由 |
|------|------|
| 存档用 SQLite 而非自定义文件 | 一对多关系（技能/背包）需要规范化存储；SQLite 零部署、事务安全、可查询调试 |
| 静态模板用 JSON 而非数据库 | 只读、需手编、带结构嵌套，文本格式最直观；与存档职责天然分离 |
| 手写 JSON 解析器而非引第三方库 | 需求面窄（只读），几百行可控、零依赖，同时满足教学目的 |
| 技能执行用 `dynamic_cast` 集中分派 | 结算逻辑集中、便于统一插桩（状态附着等）；技能类型少且稳定 |
| 背包存 `itemId→count` 而非 Item 对象 | 序列化直接（id 即主键）、避免对象重复持有；展示时再由 ItemPool 翻译名称 |
| 平台差异收敛 `console` | 战斗/交互代码零 `#ifdef`，跨平台只需改一个文件 |
| `unique_ptr` 池 + 裸指针借用 | 所有权单一路径，杜绝循环释放与泄漏；存档/战斗层只"借"不"管" |
